# 播放历史、待播队列与下载整合

本次以 `5e27f2a` 为基线，先整合 #52，再整合修订后的 #51。来源提交和作者历史均保留。正式 Release、版本号和已安装程序的更新独立处理。

| 功能 | 整合结果 |
| --- | --- |
| 播放历史 | Windows、Android 独立保存最近 500 条有效播放记录；支持回放、删除和确认清空。歌单备份和局域网分享不包含历史。 |
| 待播队列 | 展示实际顺序和当前随机计划，支持移动及下一首播放；修改会话队列不改变歌单顺序。单曲循环禁用编辑。 |
| 歌单播放 | 可以直接播放侧栏或手机选择器中的指定歌单，保留当前浏览的歌单。 |
| 下载、离线播放 | Windows 支持下载队列、进度、取消、已下载筛选和自选文件夹。下载完成的文件优先用于播放和导出。 |
| 拖拽和链接 | Windows 普通行拖拽用于排序或移动到其他歌单，Ctrl 拖拽复制；导出手柄或 Alt 拖拽用于文件导出；右键可复制原站链接。 |
| 倍速 | 双端保存 0.5–2 倍速设置；音频和受支持的官方视频后端应用该设置。暂停和预加载内容不会因改倍速而开始播放。 |

## 冲突处理

图标、背景、定位、登录、视频导航和全屏清理沿用主分支的统一实现。保留托盘、定时暂停、歌单恢复保护、分 P 归属及 Windows IPC 路径修复。歌词封面背景使用同一封面背景开关；下载与历史功能使用原有主题和弹层。

#51 中另一套图标、背景和定位控件不重复引入。其安装器、版本号变更、启动恢复策略，以及 Android 登录和 B 站页面重写未采用；这些改动需要单独的兼容性证据，不能覆盖已经整合的行为。Android 构建保留现有的路径兼容、资源校验和签名约定。

## 已修订的问题

- 队列编辑携带开始操作时的状态标识。期间自动切歌或队列变化时拒绝旧操作，避免移动另一首歌。删除历史失败后可以直接重试。
- 历史保留 B 站分 P 信息和歌曲显示名称。删除原歌单后仍能重建正确的分 P 地址。
- 下载不会覆盖目录中已有的同名文件，并发任务使用不同名称。索引不能读取或清理目录外文件；扩展名限制为音频格式。
- 下载在流中执行大小限制。取消会关闭上游流和文件，清除临时文件；退出时取消未完成任务。下载期间禁止切换目标文件夹。
- 已下载文件直接用于导出，不再重复下载一份缓存。仅悬停歌曲不触发下载；首次显式导出可能需要先准备文件。
- 跨歌单移动只修改拖拽的来源歌单，保留其他歌单中的同一首歌。目标歌单继续按歌曲标识和歌名、作者去重。
- 离线音频正确处理尾部 Range 请求和无效范围。倍速传递到首次加载、媒体元素替换及原生播放，历史计时按当前倍速判断正常进度。
- 保留系统“减少动态效果”偏好，手机窄屏播放控件可换行。

Android 的 `MediaPlayer.setPlaybackParams` 在准备完成后可能开始播放，因此原生倍速只应用到正在播放的当前音频；暂停和预加载状态仅保存设置，在正常开始播放时再应用。[Android API 说明](https://developer.android.com/reference/android/media/MediaPlayer#setPlaybackParams(android.media.PlaybackParams))。

## 验证边界

测试使用隔离歌单、本地合成媒体和受控平台响应，包含实际 Windows 主进程、preload、下载落盘、离线音频解码、跳转和取消链路。拖出文件的 IPC 参数经过检查，系统拖拽手势使用替身；这不能代替向资源管理器实际拖出文件的人工验收。

Android 原生编译、生产倍速方法回归、生成的 runtime 和双端浏览器界面分别验证。未使用 Android 真机或模拟器，未验证真实账号、付费内容、平台网络限制以及原站视频的长时间后台行为。构建和签名检查不代表这些场景已经完成。
