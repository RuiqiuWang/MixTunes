# 在线搜索添加反馈与歌单归属

Windows 和 Android 的搜索结果按实际歌单数据显示归属。添加入口仍可打开歌单选择，同一首歌曲可以继续加入其他歌单；不会因为已经加入一个歌单就禁用整个搜索结果。

- `＋`：当前没有确认归属，或上次添加失败；可以选择目标歌单。
- `…`：该结果正在添加。
- `✓`：至少有一个歌单包含该来源歌曲，说明文字显示歌单数量；选择界面逐歌单标注已存在状态。
- 添加反馈区分真正新增、同来源已经存在、同名同作者去重以及失败。同名作者但不同来源被去重时明确提示“未重复添加”，不会凭标题给新来源标记 ✓。
- 失败显示原因并保留重试入口。确认添加前取消歌单选择不提交添加请求。

## 数据来源和兼容性

后端沿用既有 canonical 导入和 PlayerEngine.addTracksDetailed，只增加明确的 added/exists/duplicate 状态、规范化 key 及未确认写入检查，不修改原去重、插入顺序、播放或歌单格式。零计数时仅当目标队列确含该 key 才能报告已存在。

共享 app/ui/search-match.js 以平台限定的稳定标识匹配本地曲目，并支持规范化 HTTPS URL 回退；不使用歌名/作者判定真实归属，也不为显示标记发起网络导入。QQ 使用 songmid，网易云使用数字 id，Bilibili 使用 BV/av 标识及分 P 页码（搜索默认 P1）；不会猜测 av 与 BV 的对应关系。无法可靠识别时保守地保持 ＋。

两端按播放器快照中的 playlists/tracks 计算已有归属，并校正本次会话的添加结果。歌曲被移出或歌单被删除后撤销失效状态；重新搜索或重启/刷新时从真实歌单重新计算，不把视觉标记单独持久化。

保留原版平台流程：Windows 切换浏览歌单会清空当前在线搜索并提示重搜，重搜后恢复真实归属；Android 保留原搜索页并随状态更新。两者的归属语义相同，不为此功能改变原查询行为。

无需托盘、睡眠定时器、背景、图标或播放定位。不增加原生桥方法、权限、依赖或用户数据迁移；Android build-web 仅追加共享身份匹配脚本。

$env:MIXTUNES_SEARCH_EXECUTABLE='<本分支打包的 MixTunes.exe>'

UI 测试模拟 API 返回；集成测试使用实际 SearchService、canonical 解析、PlayerEngine、界面和存储逻辑，只替换平台搜索/导入边界。Windows 执行真实打包 EXE、IPC 与本地库重启；Android 执行实际生成 runtime 和移动 UI，原生传输/UUID 使用受控替身，存储跨页面重载保留。

覆盖确认前取消、添加失败/重试、重复添加、多歌单归属、切换和删除歌单、移除歌曲、同名作者不同来源、重新搜索及重启/刷新。真实引擎配模拟音频后端另验证 playing/paused 状态下添加不改变歌曲、7123ms 进度和播放队列，不发出额外后端命令。

## 未验证与边界

没有据此确认三平台真实账号联网搜索/导入、实际音视频测听、Android 真机/系统 WebView 行为或全部弱网并发组合。确认前取消已测试；添加请求已经发出后关闭界面不提供撤销歌单写入功能，不宣称实现了回滚。

本功能只处理搜索结果的添加反馈和归属标记，**不修复 QQ 在线搜索失败（Fork #25）或音视频切换进度（Fork #16）**，也不改变排序或平台权限。
