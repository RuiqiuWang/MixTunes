# Windows 歌单读取失败保护

仅改变 Windows `LibraryStore.load()` 和故障后的 `save()`。Android、播放引擎、界面、导入格式和正常保存格式均不修改。本次基于已合并托盘、搜索反馈和睡眠定时器的上游 main 125b533；相对该基线只增加本项保护，不重复引入已合并功能。

## 行为与恢复

- 首次运行没有 `library.json`（ENOENT）时仍正常初始化。
- 其他文件读取错误、JSON 解析错误、空文件以及明显错误的文件结构会中止启动。原有启动错误对话框提示“已保留原文件并禁止保存”，程序退出，不创建播放引擎。
- 故障实例的所有后续保存都被锁定，不先写 `.tmp`，也不复制、删除、替换原文件。即使移除或修复文件，同一个实例也不会解除保存锁；重新启动后使用新的实例读取修复文件。
- 请先完全退出应用，把整个用户资料目录复制到其他位置。默认目录为 `%APPDATA%\MixLink`；使用显式 `--data-dir` 时以该目录为准。保留 `library.json` 原件及已有备份，然后检查文件内容和访问权限，或把确认正确的备份复制为 `library.json`，再启动应用。不要把空文件当作修复，不要直接删除唯一副本。
- 旧格式迁移仍使用已有的 `library-v1-before-migration.json` 一次性备份；不新增自动恢复或自动选择备份的策略。

## 最小结构校验

仅用于从磁盘读取的文件，在 `normaliseLibrary()` 之前执行：

- 根必须为非 null 对象，不能是数组或原始值。
- 若存在 schemaVersion，只支持数字 1、2；省略版本继续走旧格式。
- 若存在 tracks、playlists、queue，必须为数组。
- playlists 内元素必须为非 null 对象；若存在其 queue，必须为数组。

不强制字段完整、不禁止额外字段，保留 `{}`、旧格式省略字段、合法空数组、空歌单的兼容性。歌曲条目的过滤、去重、默认设置和数量上限仍由原有归一化处理；这不是完整 schema 校验，也不保证每一种语义损坏都能识别。未来 schema 拒绝读取是有意的数据保护，需使用支持该格式的版本打开。

## 测试

从仓库根目录，使用 Node >=22.12：

```powershell
node --test app/test/*.test.cjs
$env:MIXTUNES_RELEASE_EXECUTABLE = '完整路径\win-unpacked\MixTunes.exe'
$env:MIXTUNES_PROTECTION_TEST_ROOT = '隔离的证据目录'
node --test tools/library-read-protection-electron.cjs
```

单元测试覆盖有效歌曲/设置修改、首次初始化、旧格式迁移和合法空歌单、语法/结构错误、模拟 EACCES/EPERM/EIO、目录代替文件、重复/延迟/退出式保存、修复后重启。主程序测试执行真实 main 的启动和退出处理器，Electron 宿主使用替身以断言对话框文字和退出码，同时确认失败后没有创建引擎、音频、定时器或托盘生命周期。

打包集成测试真实启动指定 Windows EXE，使用全新隔离资料目录。语法错误、空文件、null 根、错误字段、未来 schema、非法编码均检查退出码 1、原始字节相同、没有临时保存文件/启动成功标记；再恢复有效含歌曲文件，验证正常启动并退出保存。另检查首次初始化和重启，以及合法旧格式迁移后开启定时器再正常退出：退出处理器取消定时器，保存的歌曲/队列和逐字节迁移备份保持正确。每个故障保留原输入及前后 SHA-256 证据。`--test-mode` 静音且不显示正常窗口；不等于真人操作验收或真实账号测听。

## 与上游 PR #19 的策略关系

比较对象为 #19 的 c39a4d1。其实现新增滚动自动备份、损坏文件副本、从非空可用备份自动恢复以及界面通知，并对写入进行 fsync；本项选择中止启动和锁定保存，避免自动决定应恢复哪个版本。

#19 的正常自动恢复有助于继续使用应用，保留损坏副本也便于事后分析。但其损坏副本创建失败被忽略；没有可用备份或读取被暂时拒绝时返回空歌单，save 并未锁定。若之后保存恢复可写，原路径可能被空歌单替换；此时若副本也未创建，可能没有原数据副本。空歌单备份不被其 readBackup 采用。上述是隔离故障模拟，不表示普通恢复流程必然丢失数据。

本项避免此类故障后的自动覆盖，但不能在故障后继续使用播放器，也不会自动恢复备份。合法但不受支持的新 schema 或错误字段会阻止启动；正常已知旧格式、空歌单已有回归。保留省略字段的兼容性意味着 `{}` 或字段丢失等语义损坏仍可能被接受。

如采用 #19，可考虑在无法确认损坏原件已安全保留或可靠恢复时借鉴本项保存锁和最小结构校验；如采用本项，可单独评估其正常备份、fsync 和恢复提示，但应让用户明确选择恢复来源。两者修改同一 load/save 区域，存在文本与行为策略冲突，不能不经设计直接叠加。

## 边界

没有更改 save-before-load 的历史 API、跨进程锁、保存期断电/磁盘故障、原有单条曲目修复、导入 JSON 校验或备份轮换。迁移备份失败原本会中止启动，但不属于本项 read/parse/envelope 保存锁；主程序仍因引擎未创建而不会退出保存。运行期间原文件被其他进程替换/删除、UNC/磁盘硬件故障、真实 Windows ACL 拒绝未完整实测；权限错误为可控模拟。不会读取真实用户歌单、修改 ACL、自动修复或清除数据。
